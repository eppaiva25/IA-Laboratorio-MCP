# Sessão de Aprendizado — 18/08/2026

## Tema

Git local como controle de versões e memória persistente do Laboratório de IA.

## Objetivo da sessão

Aprender os fundamentos do Git antes de permitir que Claude Code ou agentes de IA modifiquem arquivos do laboratório.

## O que aprendemos

### 1. Repositório Git local

O laboratório possui um repositório Git em:

V:\Claude Code\Laboratorio-IA

A pasta .git pertence ao repositório e contém as informações necessárias para seu histórico e funcionamento.

### 2. Primeiro commit

Foi criado o primeiro commit:

4c63ef8 — chore: inicializa Laboratório de IA

Esse commit representa o primeiro estado registrado do laboratório.

### 3. Working Directory

Alteramos o README.md depois do primeiro commit.

O comando:

git status

mostrou o arquivo como modified.

Aprendemos que o arquivo atual pode estar diferente da versão registrada no último commit.

### 4. git diff

O comando:

git diff

mostrou exatamente a diferença entre o arquivo atual e a versão registrada no Git.

Isso permite revisar uma alteração antes de registrá-la.

### 5. Staging Area

Aprendemos que git add não cria um commit.

Ele coloca a alteração na Staging Area, preparando-a para o próximo commit.

### 6. Memória persistente

Criamos uma estrutura de memória dentro do laboratório:

- memoria/ESTADO-ATUAL.md
- memoria/DECISOES.md
- memoria/SESSOES/

Essa estrutura foi criada para permitir continuidade entre sessões da API.

### 7. Markdown como formato principal

Decidimos utilizar Markdown como formato principal para documentação, memória, decisões e instruções do laboratório.

PDF e DOCX serão tratados como formatos derivados quando houver necessidade específica.

## Aprendizado principal

O Git não é apenas uma ferramenta para salvar arquivos.

Ele permite criar pontos conhecidos no tempo, comparar alterações e recuperar estados anteriores.

Isso poderá funcionar como uma camada de segurança quando começarmos a trabalhar com agentes capazes de modificar arquivos.

## Próximo passo

Completar o exercício prático:

lteração → git diff → git add → git diff --staged → git commit

Depois avançar para a utilização do Git no fluxo de trabalho do Claude Code.

## Observação

Durante a sessão foi reforçado o princípio de verificar informações antes de modificar arquivos. Uma pequena diferença no conteúdo do ESTADO-ATUAL.md foi identificada e corrigida somente após verificação direta do arquivo.
